- **接口**：GET 返回 `cycles`；POST 保存策略时整体重建账本；`/grid/{id}/trades` 单笔补录同样重建（旧「按摊薄成本补算」逻辑已删）。

## 网格参数「严谨正交模式」

- **三个正交维度**：生成方式(range|step)、网格模式(arithmetic|geometric，DB 列名 `mode` 即 grid_type)、步长类型(`percent`|`amount`)。默认 `step + geometric + percent`，步长 1.5%、上 5 下 6。
- **UI**：网格模式从「仅区间模式可见」改为永远显示；步长类型左=固定差价 元、右=百分比 %；等比自动锁 percent，等比下点固定差价自动切回等差（两个 watch 互相约束，无循环）。
- **公式**（P0 基准价、r 百分比、V 固定元）：等比百分比 `P0*(1+r)^k`；等差百分比 `δ=round(P0*r,3)` 后 `P0+k*δ`；等差固定元 `P0+k*V`；区间模式不变。
- **关键细节**：等差百分比必须先把单格价差四舍五入到 3 位再乘格数，否则逐档 round 会让相邻差价在 0.549/0.550 抖动，无法做到「恒定」。
- **三处同口径**：`gridCalculator.buildStepLines`、`grid_cycles.build_level_prices`（回合目标价）、`grid_backtest.run_backtest`（撮合）。
- **坑7**：`step_type` 枚举从 pct/fixed 改为 percent/amount，历史行必须迁移（`migrate_grid_orthogonal.py`），前后端都要做旧值兼容（`fixed→amount`、其余→percent），否则老策略回显会错位。
- **验证**：600298 P0=36.62/r=1.5% —— 等比节点 33.491→38.867、差价 0.502→0.574 递增、单格收益率恒定 1.50%；等差每档恒差 0.549 元；回测三组合均 17 次套利、收益 9.51%~9.53%；build 通过。

## 网格交易 6 项实盘细节修正

- **上下限自动化**：step 模式 `:disabled` + 「自动推算」微标，`watch([plan.config.lower/upper, genMode])` 实时回填最高档卖出价/最低档买入价；range 模式解除禁用（实测可改 5.000）。回填不会与 plan 循环（step 分支不读 upper/lower）。
- **最近买/卖档**：必须按 `levelStatus().code` 过滤——买档只在 idle 里取最大 buyPrice，卖档只在 holding 里取最小 sellPrice。否则会取到未持仓档的 sellPrice（第 6 档 4.140 而非第 7 档 4.202）。
- **标尺圆点**：holding 用 sellPrice、idle 用 buyPrice，右端档位才压在边框上；用 clampX 兜底。
- **卡片1**：拆成「今日 x% | 距基准 y% (基准价)」，新增 `toBasePct`。
- **含底仓占用**：`buildGridPlan` 需传 `initialCost`（否则 config 缺字段），`summary.baseCostAmount = initialCost×initialShares`（无底仓退回 holdingAmount），`maxTotalCapital = baseCostAmount + pendingBuyAmount`。
- **底仓提示**：`baseAllocationHint` 比较 `gridsUp×sharesPerGrid` 与 `initialShares`，不足/超配两种文案，建议格数 `ceil(init/per)`。
- **操作列互斥 + 高亮**：`levelRowClass` 返回 `row-nearest-buy/sell`（记得 `:deep()` 覆盖 td 背景，否则被 el-table 默认样式压掉）。

## VS Code 分屏开发（Command+Shift+B）：自动清场 + 关闭即停库

- `.vscode/tasks.json` 重写为默认 build 复合任务，`dependsOn` 两子任务 + `dependsOrder: parallel`；同 `presentation.group: "dev-split"` + `panel: "shared"` 实现底部左右分屏。
- `.vscode/scripts/{backend,frontend}.sh`：启动前按端口清场 → 左侧 `pg_local.sh start` + `uvicorn --host 0.0.0.0 --port 8000 --reload --reload-dir app`，右侧 `npm run dev`。
- **坑9（bash trap）**：直接前台跑 uvicorn 时，bash 收到 TERM/HUP 会把 trap 延迟到子进程结束，表现为「关分屏后 8000 仍被占用、库不停」；`exec` 更会让 trap 完全失效。正确写法是 `cmd & PID=$!; wait $PID`，并 `trap cleanup EXIT INT TERM HUP QUIT` + `CLEANED` guard 防重复。
- `dev.sh` 的 uvicorn 补回 `--host 0.0.0.0 --reload --reload-dir app`，与分屏脚本口径一致。
- **维护铁律（用户明确要求）**：日常由用户 Cmd+Shift+B 分屏常驻、前后端热更新；**严禁在 AI 会话中执行 `./dev.sh restart|stop`、kill 8000/3000、pkill uvicorn|vite**，改完代码只让用户刷新页面。已写入 PROGRESS 9.5。
- 实测：`kill -TERM <脚本PID>` 后左屏打印「已释放 8000 / 已关停 PostgreSQL」，右屏「3000 已释放」，pgrep 全空。vite 首次启动约 18s（Vue DevTools 插件拖慢），只监听 `[::1]:3000`，`localhost` 可访问、`127.0.0.1` 不通属正常。
