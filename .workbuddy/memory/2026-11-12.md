## 持仓页面实用性升级：最近修改时间列 + 分红除权成本试算

### 一、positions.updated_at 隔离改造
- **根因**：Position 模型 `updated_at` 带 `onupdate=func.now()`，后台「刷新现价 / 收盘一键更新」通过 ORM 更新 `current_price` 时会顺带刷新 updated_at，导致所有持仓的 updated_at 都被污染成最近一次同步时间，失去「用户最近整理时间」语义。
- **修复**：
  - 移除模型 `onupdate=func.now()`（保留 server_default）。
  - `replace_positions`（POST /api/portfolio 整数组覆盖）不再刷新 updated_at（加入排除列表，去掉 `| {"updated_at": func.now()}`）——前端「刷新现价/ROE」走此接口回写，不再污染。
  - `upsert_position`（POST/PUT /positions）显式 `| {"updated_at": func.now()}`——用户主动新增/修改才刷新。
  - 新增 `migrate_positions_updated_at.py`：存量 updated_at 统一锚定为 `2026-01-01 00:00:00+08`。
  - `PositionOut` 加 `updated_at` 字段（camelCase: updatedAt）。
- **实测**：PUT 修改 600887 成本 → updated_at 更新为当前时间；再触发 `daily_sync._step_positions()` 刷新 22 只现价 → updated_at 完全不变（隔离铁律成立）。

### 二、分红除权成本试算
- **同花顺主通道**：`ths_client.get_adjustment_factors(code, from, to)` 调 `/api/a-share/corporate-actions/adjustment-factors`，字段 `ex_date_ms`/`dividend_per_share`（每股派息）/`per_share_bonus`（每股送股比例，0.1=10送1），**无报告期字段**，用 ex_date 反推（5-7月=上一年年报）。
- **东财备用通道**：`free_client.get_dividend_preview(code)` 调 `RPT_SHAREBONUS_DET`，字段完整含 `REPORT_DATE`（报告期）/`EX_DIVIDEND_DATE`/`PRETAX_BONUS_RMB`（每10股派息）/`IT_RATIO`（每10股送转）/`ASSIGN_PROGRESS`。
- **路由** `GET /api/portfolio/positions/{code}/dividend-preview?current_cost=&current_shares=`：主通道同花顺 → 失败降级东财；除权公式 `新成本=(current_cost-cash_div)/(1+bonus_ratio)`、`新股数=int(shares*(1+bonus))`。
- **实测**：600887 伊利 2025年报 10派9.00元（除息日 2026-06-05）成本 23.396→22.496；603288 海天 10派8.00元（2026-06-15）54.948→54.148。

## 黄底行（risk-row）判定重构 + 悬停说明

- **规则**：行黄底 = `g`（3年EPS复合增速）< 10% 或 `expectedReturn`（持有3年预期年化）≤ 0，见 `evaluateRisk(row)`；样式 `.risk-row td { background:#fff7d6 }`，hover 加深为 `#fdefb8`。
- **修掉的隐患**：原 `Number(String(row.g || '').replace('%',''))` 在 `g` 为 `null`/`''` 时得到 `Number('')===0`，被误判成「零增长」而标黄。改为 `parsePercent()`：null/undefined/纯占位符 `-`/`--` 一律返回 null，`'-5.20%'` 仍正常解析为 -5.2，数字 0 仍判为命中（语义正确）。
- **悬停说明**：`.portfolio-container` 上挂 `@mousemove="handleRiskTipMove"`，用 `event.target.closest('tr.risk-row')` + `parentElement.children` 的下标回取 `tableData[index]`（不依赖 row-key，因 el-table tr 无 data 属性）；提示用 `position: fixed` 跟随光标（右下 16px，贴边自动翻转），`pointer-events:none` 防抖，`@mouseleave` / `@scroll.capture` 隐藏。内容按命中条件逐条列出「指标 / 实测值 / 告警线」，双命中（如达仁堂）显示两行。
- **配套**：`FundFlowSpark` 无数据时 `.spark-empty.compact` 补 `min-height:32px`，避免空行行高 44 vs 46 参差；名称旁 📊 从 0.68rem 提到 0.95rem（太小会糊成色块）。

## 数据库主备互换：Mac 本地 PostgreSQL 升为主库（NAS 降为冷备）

- **环境约束**：本机无 Homebrew、无 sudo、GitHub 直连超时 → `brew install postgresql@17` 不可行。改用 micromamba（`micro.mamba.pm` 静态包，装在 `~/.local/bin/micromamba`）+ conda-forge `postgresql=17`，装到 `~/.local/pg17`，数据目录 `~/.local/pgdata17`，端口 5432，`pg_hba` 对 127.0.0.1 trust 免密（同时设 postgres 密码 mypg123456）。**launchctl bootstrap 在本机被沙箱拒绝（I/O error 5），LaunchAgent 方案不可用**，改为 `~/.zshrc` 静默探活启动 + `stock-service/pg_local.sh {start|stop|restart|status}`。
- **配置**：`.env` 改为双连接 `DATABASE_URL`（本地主）+ `NAS_DATABASE_URL`（NAS 备）+ `NAS_DB_CONNECT_TIMEOUT=3`；`app/core/config.py` 用 `model_post_init` 从 DATABASE_URL 回填 `POSTGRES_HOST/PORT/DB`，`/health` 展示自动跟随真实主库，`POSTGRES_*` 降为兜底。
- **db_sync.py**：`pull-from-nas` / `push-to-nas` / `status` 三命令。DDL 走 SQLAlchemy（`create_all` + `CreateColumn` 补列 + `index.create(checkfirst=True)`），数据走 asyncpg `COPY` 经 SpooledTemporaryFile，单事务 `TRUNCATE ... RESTART IDENTITY CASCADE` + 逐表搬运 + `setval(pg_get_serial_sequence())`。
- **坑1**：内容指纹不能用 `t::text`——NAS 表是老库，`migrate_stocks.py` 等 ALTER 加的列物理上排在末尾，两端列序不同会 100% 误报差异。必须 `ROW(显式列序)::text` 再 md5 聚合。
- **坑2**：`ensure_schema` 原本在 connect 之前执行，NAS 离线时 DDL engine 抛 TimeoutError 直接 traceback。改为先 connect 再对齐结构，并统一用自定义 `SyncError`（已打印过中文原因），避免 `SystemExit` 在解释器退出时二次打印、顺序错乱。
- **结果**：15 表 / 42,587 行，pull 0.87s、push 1.62s，行数 + 指纹全一致；`positions.id` 序列校准到 309。
- **前端验证**：无头 Chrome（需 `--no-sandbox`，否则本沙箱下 GPU 进程崩溃）+ CDP 逐菜单点击，11 个页面 + 详情抽屉 K 线全部正常。已知外部问题：`/fund-flow/market-rank` 受东财 push2 限流返回 500，与库无关。

- **`dev.sh` 语义调整**：`start` = 数据库 → 后端 → 前端；`stop` = 后端 → 前端 → 数据库（先停应用再停库，`-m fast`），并做残留自查；`restart` = 先全停再全起。
